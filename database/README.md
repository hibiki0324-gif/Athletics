# Athletics Database

## 試合結果DB設計

### 設計方針

- 試合結果は試合単位で管理する
- チームはteamsで管理する
- シーズンはseasonsで管理する
- 試合に参加したチームはmatch_teamsで管理する
- イニングごとの得点はmatch_inningsで管理する
- 試合中の選手の出場・打順・守備位置はmatch_lineup_entriesで管理する
- 打撃成績はmatch_batting_statsで管理する
- 勝利投手・敗戦投手・セーブはmatch_pitching_decisionsで管理する
- バッテリーはmatch_batteriesで管理する
- シーズン成績は試合ごとの成績から集計する
- 打率やOPSなどの計算値は原則としてDBに直接保存せずAPI側で算出する
- 勝敗はスコアから判定し、重複した情報をDBに保存しない
- 選手マスタと試合中の出場情報を分離する
- 守備交代・選手交代に対応できる構造とする
- 延長戦に対応できるようイニング数を固定しない
- 現時点では1球単位・1打席単位のイベント管理は行わない

| players | 選手マスタ |

| seasons | シーズン管理 |

| match_batteries | 試合中の投手・捕手の組み合わせ |

## 出場履歴について

match_lineup_entriesでは、単純なスタメンだけではなく、

- 打順
- 守備位置
- 出場イニング
- 交代
- 守備位置変更
- 途中出場

を管理する。

そのため、同一選手が試合中に複数回登録されることがある。

例：

1番 村田 右翼 1回～5回
1番 村田 中堅 5回～7回
1番 田原 中堅 7回～終了

## 成績について

match_batting_statsを試合ごとの実績データとして保持し、
シーズン成績はこのデータを集計して算出する。

例：

打率 = 安打数 / 打数

OPS = 出塁率 + 長打率

など。

## 現時点で管理しない情報

現時点では以下は管理対象外とする。

- 1球ごとの投球データ
- 1打席ごとのイベント
- 詳細な投手成績
- エラー記録
- 得点イベント
- 守備イベント

将来的に必要になった場合は別テーブルとして拡張する。
